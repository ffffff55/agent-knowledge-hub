# 社区贡献：未审关闭、署名，以及拉黑

社区 PR 由 agent 审查和合并。两件事防止项目被拖垮：可能伤害用户的 PR，在还没跑它做什么之前先拦住；长期提交低质量代码、审查成本高于收益的作者，要停下来。

## 先看有没有伤害

跑 PR 之前，先读 diff，看有没有超出其声称目标的部分。出现下面任一情况，审查停住，等维护者看过再继续：

- 改了 CI、工作流、权限、密钥、发布脚本、Dockerfile 或文档站点发布配置
- 新增网络地址、上传、遥测，或把凭证、token、cookie、文件发到以前不会去的地方
- 读写与目标无关的凭证、钥匙串或本机配置
- 新增依赖、replace、安装脚本、二进制、压缩/编码混淆内容，或运行时从字符串拼出代码
- 加入中转、转售、广告或维护者已经排除的供应商

在审查评论里写明是哪一行拦住的。维护者放行之前，不要在有真实账号的机器上跑这个 PR 的代码。

## 不用完整审查就关闭

下面这类 PR 写一句简短理由后关闭，不必跑：

- 改了维护者已经拍板的决定（见 code-standards 里的「不要推翻已经拍板的产品决定」）
- 因该想法被关过、又没有新内容回应关闭理由的再提交
- 几秒内开出的一批几乎相同的 PR

## 给报告人署名

用了报告人的补丁、夹具、请求体、报错原文或根因，commit 里要带 `Co-authored-by`。只是报了「坏了」的，在正文写 `#编号, login` 即可。

## 提议拉黑

出现下面任一情况，agent 只能提议，不能自己拉黑。把证据（PR 号、日期、错在哪）写给维护者，由维护者决定：

1. 至少 3 个 PR 被维护者判定为低价值（错误、未测、无关、机器灌水），且合并率低于 30%
2. 被明确拒绝后，又用同一想法再提交两次
3. 有欺骗：在声称目标外藏改动、伪造测试或验证，或故意做了「先看有没有伤害」里的事
4. 以机器频率连开多个低价值 PR
5. 被拒绝后再次加入已移除的供应商、中转或广告

被拉黑作者的新 PR 和 issue，统一回复：`Thanks — this account's contributions aren't accepted in this repository.` 不再争论。

尚在观察（一两次低价值、还没有形成模式）的作者，照常审查，并在本文件记下这次问题。
